# Metrics

## Driving metrics (`trip_metrics` table, SQL in `metrics/driving.py`)

Each metric is computed per `(vehicle_id, trip_id)` over the committed `telemetry` rows. A *step* is the gap between two consecutive accepted samples of a trip. Only steps of 0.2 s or less (20 Hz with one missing sample tolerated) count as observed.

| Column | Definition |
|---|---|
| `samples` | Accepted rows; quarantined rows are not included. |
| `duration_s` | `last ts − first ts + 1/20 s`. |
| `distance_km` | Trapezoid rule `Σ (v_i + v_{i-1})/2 · dt` over observed steps. A dropout adds **no** distance. |
| `observed_s` | Sum of observed steps. |
| `completeness` | `samples / (duration_s · 20 Hz)`, capped at 1. |
| `speed_mean`, `speed_max` | Over accepted samples (m/s). |
| `accel_long_abs_p95`, `accel_lat_abs_p95` | 95th percentile of `|a|` (m/s²), a smoothness profile defined for every trip. |
| `jerk_abs_p95` | 95th percentile of `|Δa_long / dt|` over observed steps (m/s³). |
| `lead_present_frac` | Share of samples with a tracked in-lane lead. |
| `close_following_frac` | Among samples at ≥ 10 m/s, the share with headway `lead_dist / speed` < 1 s. |
| `gnss_availability` | Share of samples with a GNSS fix (`lat` is not NULL). |
| `quarantined_rows` | Rows of this trip that failed validation. |
| `safety_events`, `data_quality_events` | Mined scenarios of this trip: safety types vs. `sensor_dropout` / `gnss_outage`. |
| `safety_events_per_100km` | `safety_events / distance_km × 100`. NULL when there is no distance. |

## Fleet KPIs (`fleet_summary`)

Ratios are aggregated with **weights**. Averaging per-trip ratios would let a 10-second trip count as much as a 2-hour drive.

| KPI | Aggregation |
|---|---|
| `distance_km`, `driving_hours` | `Σ distance_km`, `Σ observed_s / 3600` |
| `completeness` | `Σ samples / Σ (duration_s · 20)` |
| `quarantine_rate` | `Σ quarantined / (Σ samples + Σ quarantined)` |
| `safety_events_per_1000km` | `Σ safety_events / Σ distance_km × 1000` |
| `close_following_frac` | Weighted by observed time |
| `gnss_availability` | Weighted by samples |

`event_rates()` gives the rate of each scenario type per 1000 km, split by `source`. Real, amplified and synthetic driving are kept apart because their event rates differ by construction. `fleet_hourly()` rolls the streaming `windows_10s` table up to hours.

`tests/test_metrics.py` checks these definitions against hand-computed values: dropouts, partial GNSS, a known headway, quarantine attribution and distance weighting. It also checks that the streaming windowed distance and the batch trapezoid distance agree to within 1%.

## Pipeline metrics (Prometheus, `:<metrics-port>/metrics`)

| Metric | Type | Labels | Meaning |
|---|---|---|---|
| `fleetscope_records_consumed_total` | counter | | Kafka records consumed |
| `fleetscope_bytes_consumed_total` | counter | | Payload bytes consumed |
| `fleetscope_chunks_total` | counter | `outcome` = accepted / duplicate / dlq | Chunk admission |
| `fleetscope_rows_total` | counter | `status` = valid / invalid | Row validation |
| `fleetscope_invalid_rows_total` | counter | `rule` | Quarantined rows by failed rule; one row can fail several rules |
| `fleetscope_dlq_total` | counter | `reason` | Dead-lettered records |
| `fleetscope_late_rows_total` | counter | | Rows that arrived after their window was emitted |
| `fleetscope_windows_emitted_total` | counter | | Closed 10 s windows |
| `fleetscope_files_written_total`, `fleetscope_file_bytes_written_total` | counter | `table` | Committed Parquet output |
| `fleetscope_checkpoints_total` | counter | | Committed epochs |
| `fleetscope_batch_process_seconds` | histogram | | Processing time per consumed batch |
| `fleetscope_checkpoint_seconds` | histogram | | Epoch commit time: flush + fsync + checkpoint |
| `fleetscope_ingest_latency_seconds` | histogram | | Broker append → processed |
| `fleetscope_commit_latency_seconds` | histogram | | Broker append of an epoch's oldest record → epoch visible in the lake (end-to-end freshness) |
| `fleetscope_consumer_lag_records` | gauge | `partition` | High watermark − next offset |
| `fleetscope_open_streams`, `fleetscope_open_window_streams`, `fleetscope_buffered_rows` | gauge | | Operator state size |

Label sets are small, fixed enums. `partition` appears only on the lag gauge, so cardinality does not grow with the fleet. The Grafana dashboard `infra/grafana/dashboards/fleetscope-pipeline.json` is generated by `infra/grafana/build_dashboard.py`, and CI checks that the two are in sync.

Each processor also appends its cumulative counters to `lake/_ops/health-<name>.jsonl` every few seconds. The Streamlit *Pipeline health* tab reads these files, so pipeline health stays visible without Prometheus.
